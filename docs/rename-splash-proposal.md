## 一、应用现状（写代码前必读）

- 包名（不可改）：`com.aizeek.phonepulse`——改包名会被系统当新应用，用户数据全丢
- 当前应用名：**PhonePulse**（三语言 strings.xml 已统一；原上游名 ScreenPal 已清除）
- 版本线：1.0.x（上游已发 1.0.9，本仓库是独立演进版）
- UI：全局"珍珠浅色 Bevel"体系（奶油白×薰衣草×薄荷×冰川蓝）+ 森林页保留独立深色世界
- 合规红线：**纯本地、零网络权限、不上传任何数据**（这是产品卖点）；不能引入 WebView/HTML 页面

## 二、全应用功能清单（给讨论 AI 的完整上下文）

### 1. 屏幕状态监测（核心数据源）
- 前台服务（ScreenTrackerService）常驻监听亮屏/熄屏；30 秒内短熄屏视为"连续使用"宽限合并，长熄屏才切分会话
- 会话按天切分入库（Room，版本 5，手写迁移，禁用破坏性迁移）
- 今日累计亮屏/熄屏、唤醒（解锁）次数、最近/全部会话时间线、24 小时逐小时分布图
- 当前状态实时计时（亮屏中/熄屏中，首页顶部与顶部栏同步显示）

### 2. 电池健康估算（intervention，参赛创新点）
- 正式估算：基于完整充放循环（跨度 ≥25% + 覆盖 ≥90%）的容量保持率，带置信等级
- 快速粗估：短充电会话（跨度 ≥8%）的中位数快估，作为冷启动期的低置信参考
- 设计容量解析优先级：用户手填 → 系统 sysfs（部分机型锁死）→ 内置机型标称表（如 K70 Pro = 5000mAh）
- 45%~140% 区间外的结果**标注异常但绝不隐藏数值**（传感器偏差透明呈现）
- 关键页面：电量统计 → 电池健康卡（容量保持率、估算容量、设计容量、样本证据链）

### 3. 电池实时监控与充电保护
- 每 5 秒采样电流/电荷计数（亮屏/充电时），15 秒心跳刷新状态
- 充放循环自动切分（充电段/耗电段），支持排除异常会话
- 充电提醒：到达目标电量（如 80%）本地通知，可静音；MIUI 通知权限引导

### 4. 应用使用统计
- UsageStatsManager 聚合前台时长（今日/近 24 小时/近 7 天），应用图标与名称系统缓存
- 单应用详情页：今日时间线（前台/后台事件流重建）
- 电量页交叉视图：前台时长与电量变化并排（不做伪归因，注明"活跃占比非耗电归因"）

### 5. 使用教练（行为干预引擎，参赛创新点）
- 每日亮屏预算（分钟）+ 连续使用上限（分钟）双轨提醒，各自每日冷却
- 短熄屏宽限（15/30/60s 可调）合并判定；跨天自动重置
- 提醒走系统通知（预算用完/即将到达/连续超时三级）
- 全部参数运行时可调（演示可把预算调到 1 分钟看即时效果）

### 6. 脉搏星球（游戏化主视觉，参赛创新点）
- 首页 Hero：珍珠材质星球，四种视觉状态由真实教练数据驱动——
  平稳（萌芽期）/ 节奏良好（达成 streak）/ 建议休息（连续超限或预算达 85%）/ 休息中（熄屏）
- 球体色带固定为品牌资产（薄荷→冰蓝→珍珠粉→薰衣草），阶段只换光晕与点缀色
- 轨道环 = 真实预算进度（珍珠白彗星常驻绕行，超预算变淡珊瑚粉）
- 星球详情页：7 天周报、连续达成天数、星球相位
- 性能已专项优化：位图缓存 + 每帧零分配 + 数据流去重（P95 16ms / 卡顿帧 0.73%）

### 7. 森林小窝（companion，既有模块轻量联动）
- 兔子/松鼠角色 + 木屋家具布置 + 成长任务 + 旅途明信片（可分享）
- 数据来自真实屏幕行为（今日使用摘要喂给提示语），可在首页卡片直达

### 8. 状态明细与设置
- 全部历史会话时间线（可筛选亮屏/熄屏、清除）
- 设置页：服务开关、电池优化白名单、使用情况权限、通知权限、厂商自启引导、版本与更新检查（GitHub Releases）

### 9. 数据与隐私
- 全部数据本地：Room（会话/电池记录/循环）+ SharedPreferences（教练参数/ companions 状态）
- 无 INTERNET 权限；更新检查走系统浏览器 Intent 而非应用内网络请求
- 演示数据只用团队真机（Redmi K70 Pro），不触碰他人隐私

### 10. 技术栈
- Kotlin 2.2 + Jetpack Compose（Material3，BOM 2024.09）+ Room + Coroutines/Flow + 前台服务
- 255 个单元测试全绿；R8 Release 为演示推荐形态
- 已知边界：HyperOS 把整机刷新率钉在 60Hz 时，App 自动适应（已发高刷软请求，系统放开即自动 120Hz）

## 三、改名思路

**值得做的前提**：如果新名字是为了参赛区分度/品牌叙事（与上游 ScreenPal 彻底切割），值得；如果只是"想换个感觉"，收益低——名字会牵动承诺书、官网提交、答辩口径，截止前一天要一次改对。

改名牵动的位置（机械但分散）：
1. 三语言 `strings.xml` 的 `app_name`（launcher 桌面名、顶部栏标题共用）
2. UI 内所有出现应用名的地方（顶部栏走 stringResource，已集中）
3. 单元测试里的名称断言（有 UI 测试断言 app 名）
4. 新仓库 README/描述（仓库刚建，趁早）
5. 竞赛材料（承诺书、官网、视频口播）——**必须与 APK 内名字一致**

命名方向候选（结合"屏幕休息 + 电池健康 + 星球"叙事）：
- **屏息 / PingXi**：一语双关（屏幕 + 休息 / 屏住呼吸），中文品牌感强，星球是"屏息时刻"的具象化
- **息屿 / Xiyu**：休息的岛屿，星球=情绪化身的延伸意象
- **脉息星球 / PulsePlanet**：延续 PhonePulse 的"脉搏"，把星球提为品牌主角（改动最小，故事最顺）
- 保留 PhonePulse：已统一三语言，改动成本为零

建议：选一个"中文主名 + 英文副名"的组合（如：屏息 PingXi / 脉息星球 PulsePlanet），launcher 显示中文，代码内仍是 stringResource 单点切换。

## 四、启动封面思路

三种方案（按风险从低到高）：

**方案 A：系统级 SplashScreen API（androidx.core.splashscreen）——最推荐打底**
- Android 12+ 系统原生支持：图标 + 纯色背景 + 退出动画；12 以下自动降级
- 改动：gradle 加一个 androidx 依赖 + 主题属性（背景=珍珠底色、图标=星球）+ `installSplashScreen()` 一行
- 优点：不白屏、零崩溃面、评审冷启动即有品牌感；缺点：定制空间小（只有图标和颜色）

**方案 B：Compose 品牌封面页**
- setContent 里先渲染一个全屏品牌页（星球呼吸 0.8~1.2s + 应用名 + slogan），淡出进入 MainScreen，点击可跳过
- 优点：完全可控、最能"出片"；缺点：冷启动等待感变长、要在 MainScreen 前挂状态、要保证服务启动不被阻塞

**方案 C：A + B 轻量混合（推荐组合）**
- 系统开屏保证过渡不白屏，进 App 后星球做一次 0.8s 呼吸放大交接给首页 Hero（视觉连续：封面星球=首页星球同材质）
- 工作量估计：半天内含真机回归；截止前一天可行

注意事项：
- 不做长时间强制开屏（评审反感），可跳过或 ≤1.5s
- 封面星球必须复用首页同款珍珠材质（保持视觉一致，别做第二套视觉）
- 服务启动（ScreenTrackerService.start）在 Application/Activity onCreate 已有，别挪进封面动画之后
- 改名与封面一起做时：封面文案用新名字，一次成型
